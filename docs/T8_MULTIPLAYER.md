# T8 五人多人联机

## 玩家操作

房主：打开游戏，选择「多人游戏」→ 填写玩家名称和端口 →「创建房间」。房间页显示本机局域网地址和端口，把它告诉同一局域网中的朋友。其他真人都准备后，点击「开始游戏」。空座位此时自动补成 AI。

来宾：选择「多人游戏」→ 输入房主的局域网 IP、端口和玩家名称 →「加入房间」→「准备」。无需账号。最多五名真人；可用 1–5 名真人开局。

各玩家会分别看到自己的身份与十名武将候选。每名武将只能被一人选中；若所选武将已被别人锁定，服务器会重新给候选池。对局中的手牌、按钮和请求只对应自己的座位。读条由服务器计时，默认 30 秒。

## 网络与防火墙

房主在 `0.0.0.0` 监听 TCP，默认端口 `28765`，创建房间时可以修改。房主自己也通过 `127.0.0.1` TCP 客户端连接，同样只得到自己的投影。如果朋友无法加入，确认双方可以互访，并在房主电脑的防火墙中允许此程序接收所选 TCP 端口的入站连接。第一版适用于同一局域网或可直接访问房主 IP 的网络；不提供 NAT 穿透或公网房间码。

## 架构

`GameServer` 持有唯一的 `MultiplayerRoom` 和 `GameSession`。`GameSession` 继续使用原有 `GameEngine`、`ResolutionStack`、`PendingRequest`、`Decision`、`CardMoveService`、`RandomSource` 和 AI 决策器。只有服务器初始化身份、武将池、牌堆和游戏状态，客户端不运行规则引擎。`NetworkDecisionProvider` 把真人请求发送到对应座位并校验返回的请求 ID、归属和选择；AI 座位沿用 `AIDecisionProvider`。

通讯使用按行分帧的 UTF-8 JSON over TCP，`PROTOCOL_VERSION = 1`。每条消息都必须含 `type` 和 `version`；单条消息上限为 256 KB。连接先发送 `HELLO`，版本不符时服务器以 `ERROR` 明确拒绝。之后使用 `JOIN_ROOM`、`LOBBY_STATE`、`READY`、`START_GAME`、`DRAFT_REQUEST`、`PROJECTION_UPDATE`、`PENDING_REQUEST`、`SUBMIT_DECISION`、`DECISION_RESULT`、`PUBLIC_EVENT`、`PING/PONG`、`PLAYER_DISCONNECTED`、`PLAYER_RECONNECTED`、`TAKEOVER_AI` 和 `GAME_OVER`。

服务器为每个座位单独生成 `TableView` 投影。其他玩家的手牌只显示数量；隐藏身份和十选一候选也仅发给本人。公开事件使用明确字段的白名单，不传私有移牌事件或卡牌实例 ID。客户端即使检查网络包，也不会收到别人的隐藏手牌或候选。服务器再次验证每条决策，不相信客户端提供的玩家 ID。迟到、重复、错误归属和非法选择不会推进游戏。

## 断线与重连

加入成功后服务器签发随机 reconnect token。客户端断线后自动尝试用此 token 恢复原座位；服务器发送最新房间状态、本人投影以及本人尚未到期的请求和剩余时间。断线时座位保留，当前请求到期后服务器按规则自带的合法 fallback 决策继续。房主可在房间页对断线座位点击「AI 接管」；接管从下一个请求开始，不修改角色状态。

## 已知限制

房主进程关闭后房间结束；没有独立常驻服务器或迁移房主。重连凭证只在当前服务器进程中有效。没有账户、聊天、中央大厅和 NAT 穿透。当前多人操作栏提供规则允许的选项和手牌/目标交互；观星等复杂请求以文字选项呈现，未完全复刻单人模式的专门交互布局。
