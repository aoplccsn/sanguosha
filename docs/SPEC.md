# 需求规格

## 产品与边界

- 本地离线 Windows 桌面游戏；Python 3.12+、PySide6、pytest、`src` layout、`pyproject.toml`；核心无需 Qt 即可完整运行。
- 五名玩家：一名真人、四名 AI；身份为主公 1、忠臣 1、反贼 2、内奸 1。身份、武将、牌堆和随机源可由测试固定。
- 游戏必须支持标准版、EX、军争篇的经典卡牌与首批经典标准武将。第一批不使用界限突破技能；风火林山为后续扩展。
- 以完整身份胜负、回合阶段、响应、嵌套结算、濒死、伤害与连环、判定与改判、装备和距离为交付条件，不以能显示画面或能跑一局作为规则完成标准。

## 功能需求

| ID | 要求 | 验收证据 |
|---|---|---|
| F01 | 创建五人局并可固定座次、身份、武将、牌堆、起手牌和 RNG | 构造同一 fixture 得到相同初态 |
| F02 | 所有行为由命令入口验证并生成合法选择请求；人、AI、测试使用同一种 `Decision` | 同一脚本选择可无界面复现 |
| F03 | 标准回合与阶段，支持跳过、额外回合、摸牌数和手牌上限修正 | 阶段事件和边界测试 |
| F04 | 卡牌、技能通过注册的效果/触发/修正接口扩展 | 新测试牌和测试技能不修改核心调度器 |
| F05 | 杀闪、锦囊与无懈、多人目标、濒死求桃等可暂停恢复 | 嵌套流程测试和状态快照 |
| F06 | 所有实体牌仅经统一移动服务改变区域 | 区域唯一性断言与 CardMoved 日志 |
| F07 | 伤害来源、属性、修正、防止、连环传播及濒死完整 | 属性传播和中途死亡测试 |
| F08 | 判定、反复改判、判定牌归属完整 | 改判链与弃置/获得测试 |
| F09 | 身份胜负与奖惩在死亡后按规则结算 | 所有关键死亡组合测试 |
| F10 | 结构化日志、状态版本及可展示文案 | 确定性日志断言；未来 replay 可验证 |

## 非功能要求

- 正确性 > 可测试性 > 可扩展性 > 可读性 > 性能。状态变更原子化且可审计；非法选择不改变状态。
- 核心模块不依赖 PySide6、窗口、定时器或真实时间。UI 只读取玩家可见投影与合法请求，提交决策。
- 对隐藏信息实行可见性投影：AI/真人只能看到其权限内的牌和身份；完整状态仅服务端核心/测试持有。
- 引擎的每一步确定性：相同初态、随机流和决策流产生相同事件序列与终态。
- 单机进程内权威状态；T0 不设计联网、存档格式或防作弊协议。日志为将来 replay 留数据契约，但 replay 实现延后。

## 术语

`Command` 是意图；`Action` 是验证后进入结算的工作项；`Event` 是带时点与上下文的事实通知；`Trigger` 是技能对事件的候选反应；`Effect` 是通过受控服务产生状态变化的执行器；`DecisionRequest` 是结算所需的选择；`Decision` 是对此请求的一次答复。可修改的前置窗口应使用明确的上下文/修正器，不能把已发生事实的事件倒改。

## 完成定义

T0 完成标准：文档能指导实现嵌套结算与统一选择协议；目录/模块依赖清楚；规则歧义被登记为后续需核对的决策，而非悄悄简化；各阶段有独立 PASS 门槛。T0 不等于规则数据或产品实现完成。
